# Work Review 证据星图界面模板设计规格

日期：2026-08-14  
状态：已批准实施  
目标分支：`codex/evidence-star-map-ui`

## 1. 背景与目标

Work Review 当前界面是一套成熟、稳定的桌面效率工具界面，但以固定侧栏、标准卡片网格和常规过渡为主，缺少独有的视觉叙事。此次改造不替换现有界面，而是在设置中增加第二套可选模板“证据星图”。

核心视觉概念：

> 时间作为材料，证据形成轨迹，成果从轨迹中展开。

本阶段目标：

1. 完整保留现有“经典模式”，并继续作为默认模板。
2. 增加“证据星图”模板，提供独立应用外壳、概览视图和时间线视图。
3. 两套模板共享业务逻辑、数据访问、路由和持久化机制。
4. 所有功能性图标统一使用 Lucide 图标，界面不使用 Emoji 或字符代替图标。
5. 建立可持续扩展的设计 Token、动效和模板架构，为后续迁移日报、助手和设置页面提供基础。

## 2. 范围

### 2.1 本阶段包含

- 新增全局界面模板配置：`classic` 与 `evidence-star-map`。
- 设置页增加“界面模板”选择器。
- 经典模式保持当前结构和视觉行为。
- 证据星图模式新增：
  - 独立应用 Shell。
  - 紧凑轨道式导航。
  - 概览页面。
  - 时间线页面。
  - 核心页面切换和证据聚焦动效。
- 日报、助手、设置等未迁移页面在证据星图 Shell 内安全复用经典页面。
- 接入 Lucide Svelte 图标包。
- 清理本阶段触及组件中的 Emoji、字符图标和手写功能性 SVG。
- 明暗主题、系统主题、减少动效、键盘操作和性能降级。
- 配置迁移、组件状态、核心视图和视觉回归所需测试。

### 2.2 本阶段不包含

- 不重写日报编辑器、助手和完整设置页的信息架构。
- 不删除现有 `ui_visual_style = a/b/c`；它继续服务经典模式。
- 不修改 README。
- 不上传、删除或改动本地产品演示视频、音频和字幕。
- 不引入 WebGL、Three.js 或持续运行的 Canvas 渲染循环。
- 不改变采集、隐私、AI、日报生成和数据导出的业务语义。

## 3. 用户体验

### 3.1 模板选择

路径：`设置 → 外观 → 界面模板`

选项：

- 经典模式：默认、稳定，使用现有 Shell 和页面。
- 证据星图：实验性视觉模板，使用新的 Shell、概览和时间线。

行为：

1. 初次安装和旧配置升级后默认使用经典模式。
2. 用户选择模板后立即预览。
3. 选择自动保存到本地 `config.json`，重启后保留。
4. 保存失败时恢复前一个模板，并显示可理解的错误提示。
5. 快速连续切换时，以最后一次选择为最终状态。
6. 切换模板时保留当前路由；能够保留的页面状态不主动清空。

### 3.2 证据星图 Shell

布局由三层组成：

1. 左侧窄轨导航：品牌、概览、时间线、日报、助手、设置和录制状态。
2. 中央工作画布：页面标题、核心指标、证据轨迹和时间切片。
3. 右侧上下文检查器：仅在概览和时间线需要时显示所选证据、筛选或下一步操作。

宽度不足时，右侧检查器改为可关闭抽屉；导航保持紧凑，不退化为固定宽侧栏。

导航必须使用 Lucide 图标并具备文本提示、`aria-label`、键盘焦点和 `aria-current="page"`。

### 3.3 概览页面

概览回答三个问题：

1. 今天投入了多少有效时间？
2. 证据集中在哪些工作流和应用？
3. 哪些证据可以用于生成日报？

页面结构：

- 超大时间指标作为视觉锚点。
- 证据场将来源、决策、输出三个层级映射为轨迹。
- 节点代表已脱敏的应用、页面、文档、会议或产出片段。
- 下方保留按小时展开的日轨，兼顾快速扫描。
- 右侧检查器展示当前选择、证据数量和“生成日报草稿”入口。

交互：

- 悬停节点时仅显示最必要的信息，不覆盖其他证据。
- 单击节点进行稳定选择，右侧检查器同步更新。
- Shift 或平台等价组合键支持多选。
- 点击时间段进入时间线并携带对应日期和时间范围。
- 图形表达必须有文本摘要，不能只依赖颜色或空间位置。

### 3.4 时间线页面

时间线继续支持现有日期、分页、查看详情、分类和隐私相关能力，但改用“证据带”布局：

- 横向时间轴作为主要方向。
- 应用、网页、文档、会议等证据以不同轨道排列。
- 当前时间和选中时间范围具有清晰标记。
- 详情在右侧检查器或窄屏抽屉展示。
- 截图仅在用户允许且数据存在时显示；脱敏和忽略状态保持原有语义。
- 大数据量继续分页，并为后续虚拟列表预留边界；本阶段不重写后端分页协议。

### 3.5 未迁移页面

日报、助手、设置和关于等页面继续使用现有页面组件。证据星图 Shell 为它们提供统一背景、导航和内容容器，但不强行套用星图轨迹布局。

这样可以避免一次性重写全应用，并保证用户随时可以回到稳定功能。

## 4. 视觉系统

### 4.1 设计语言

- 基础空间：深黑石墨背景，低对比网格和微弱体积光。
- 主要强调色：酸性黄绿色，用于主操作、当前状态和关键节点。
- 次级强调色：青色与紫色，用于证据类别和轨迹关系。
- 信息层次优先依靠字号、间距、透明度和位置，不依赖大量卡片边框。
- 大字号数据与紧凑等宽标签形成编辑式排版对比。
- 避免通用渐变卡片、彩色光晕堆叠和装饰性图标。

### 4.2 Token 边界

证据星图使用模板局部 Token，全部置于：

```css
[data-ui-template="evidence-star-map"]
```

Token 至少包含：

- 背景、面板、边框和文本颜色。
- 三种证据强调色。
- 字体尺寸和字距。
- 页面间距和导航尺寸。
- 阴影、模糊和透明度上限。
- 动效弹簧曲线、快速反馈和页面过渡时长。

经典模式的 Token 和 CSS 不被新模板覆盖。证据星图组件优先使用局部样式或独立样式模块，不继续向现有超大全局 `app.css` 堆叠页面级选择器。

### 4.3 图标规则

- 新增 `lucide-svelte` 作为唯一功能性图标来源。
- 图标尺寸、描边宽度和颜色通过统一封装组件控制。
- 数据可视化轨迹、轴线和连接线不属于功能性图标，可使用语义化 HTML、CSS 或专用 SVG 图表实现。
- 界面中禁止 Emoji。
- 禁止用 `✓`、`✗`、`✎`、`×` 等字符承担按钮图标职责。
- 品牌标志和数据可视化不强制使用 Lucide。

## 5. 动效与交互反馈

### 5.1 原则

- 动效用于解释空间关系和状态变化，不作为持续装饰。
- 不使用滚动劫持、鼠标跟随背景或持续高频粒子系统。
- 所有操作必须在无动效时仍能理解和完成。

### 5.2 动效层级

1. 即时反馈：80–140ms，用于按钮按压、焦点和悬停。
2. 组件变化：180–320ms，用于检查器、筛选和节点选择。
3. 页面空间变化：360–520ms，用于概览与时间线之间的轨迹展开。

使用近似弹簧的缓动，但不引入需要持续运行的物理引擎。布局变化优先使用 transform 与 opacity，减少昂贵的模糊和布局重排。

### 5.3 减少动效

在 `prefers-reduced-motion: reduce` 下：

- 取消轨迹绘制、节点漂移和视差。
- 页面切换缩短为淡入淡出或直接切换。
- 禁止自动循环动画。
- 保留焦点、选择和加载状态的非运动反馈。

## 6. 技术架构

### 6.1 配置模型

新增独立配置字段：

```ts
type UiTemplate = 'classic' | 'evidence-star-map';
```

职责区分：

- `ui_template`：决定 Shell 和核心页面结构。
- `theme`：决定 `system/light/dark`。
- `ui_visual_style`：继续决定经典模式现有 `a/b/c` 外观。

Rust `AppConfig` 为 `ui_template` 提供默认值、归一化、序列化和旧配置兼容。根节点同步：

```html
<html data-ui-template="classic">
```

或：

```html
<html data-ui-template="evidence-star-map">
```

### 6.2 组件边界

```text
AppRoot
├── TemplateRegistry
├── ClassicShell
│   ├── ClassicSidebar
│   └── SharedRouter
└── EvidenceShell
    ├── EvidenceNavigation
    ├── EvidencePageFrame
    ├── EvidenceInspector
    └── SharedRouter
```

核心页面拆分：

```text
OverviewController / OverviewViewModel
├── ClassicOverviewView
└── EvidenceOverviewView

TimelineController / TimelineViewModel
├── ClassicTimelineView
└── EvidenceTimelineView
```

实施时不复制 Tauri 请求、缓存、分页、删除、分类、隐私或日期格式化代码。先把现有页面中的可复用数据转换抽成纯函数和 ViewModel，再接入新视图。

### 6.3 状态流

推荐统一状态流：

```text
SettingsAppearance
  → 更新模板 Store/Cache
  → AppRoot 即时响应
  → save_config 持久化
  → config-changed 校准最终状态
```

模板切换保存需要请求序号或等价的最后写入保护，避免早期请求覆盖最新选择。失败回滚必须同时恢复设置控件、全局缓存和根节点属性。

### 6.4 渲染策略

- 第一阶段使用 Svelte、DOM、CSS 和受控 SVG 数据可视化。
- 不引入 WebGL。
- 轨迹只在数据或选择变化时更新，不使用永久 `requestAnimationFrame`。
- 页面隐藏、路由离开或减少动效时停止非必要动画。
- 右侧检查器和浮层使用语义化组件，避免不可访问的纯 `div` 点击区。

## 7. 数据、错误和边界状态

必须覆盖：

- 无数据：展示引导和录制状态，不生成虚假轨迹。
- 加载中：使用稳定骨架或进度状态，避免布局跳动。
- 部分数据缺失：保留可用证据，并显示简短说明。
- Tauri 命令失败：保持当前视图和用户选择，显示非阻塞错误。
- 截图关闭：轨迹仍可通过应用、标题、时间和分类工作。
- AI 关闭：日报入口继续支持基础模板生成；不得暗示 AI 已启用。
- 极长应用名和页面标题：截断但可通过可访问名称读取。
- 跨日、空白时段和大量记录：保持时间轴稳定，不产生重叠不可读节点。

## 8. 无障碍要求

- 所有功能按钮使用真实 `button` 或语义等价控件。
- Lucide 图标为装饰时 `aria-hidden="true"`；独立图标按钮必须有 `aria-label`。
- 导航当前项使用 `aria-current="page"`。
- 弹层和抽屉处理焦点进入、循环和返回。
- 图表提供文本摘要或隐藏数据结构。
- 证据类别不只靠颜色区分，同时使用标签、形状或文字。
- 键盘可以完成模板切换、导航、证据选择、查看详情和关闭检查器。
- 焦点样式在深色背景下满足清晰可见要求。

## 9. 性能预算

- 不增加持续运行的 Canvas/WebGL 渲染循环。
- 单个页面同时使用 `backdrop-filter` 的大面积层不超过两个。
- 动画优先限制在 transform、opacity 和少量可控 SVG 属性。
- 时间显示按实际精度更新；只显示分钟时不每秒触发全页更新。
- 大量时间线记录继续按页加载，避免一次性渲染全部历史数据。
- 构建产物新增图标必须保持可 tree-shake，不全量打包 Lucide 图标库。

## 10. 测试与验收

### 10.1 配置测试

- 默认 `ui_template` 为 `classic`。
- 旧配置缺少字段时正常迁移。
- 合法值正常保存，非法值回退到 `classic`。
- 重启后保持用户选择。
- 快速切换最终以最后一次选择为准。
- 保存失败完整回滚。

### 10.2 前端测试

- 模板解析与根属性同步。
- ClassicShell 与 EvidenceShell 按配置正确选择。
- 未迁移页面在 EvidenceShell 中安全显示。
- 概览 ViewModel 和时间线 ViewModel 对空数据、缺失数据和大量数据输出稳定。
- 证据选择、多选、清空和跨页面时间范围传递。
- Lucide 图标按钮具备可访问名称。
- 减少动效模式禁用非必要动画。

### 10.3 回归测试

- 经典模式概览、时间线、日报、助手、设置、录制状态和窗口控制无行为变化。
- 明暗主题与现有 `a/b/c` 视觉风格继续工作。
- Rust 配置测试、Svelte 静态检查、前端测试和生产构建通过。
- 关键页面在典型桌面尺寸和窄窗口下进行视觉检查。

### 10.4 完成标准

- 用户可在设置中切换两套模板并持久保存。
- 经典模式默认且无可见回归。
- 证据星图模式拥有独立 Shell、概览和时间线。
- 触及范围不包含 Emoji 或字符功能图标，新图标全部来自 Lucide。
- 无障碍、减少动效和错误回滚具备自动化或可重复验证证据。
- 不修改 README，不提交演示视频资产。

## 11. 实施顺序

1. 配置模型、模板 Store 和测试。
2. Lucide 图标基础设施与本阶段图标治理。
3. ClassicShell/EvidenceShell 边界。
4. 设置页模板选择器和保存回滚。
5. 概览数据逻辑抽取与 EvidenceOverviewView。
6. 时间线数据逻辑抽取与 EvidenceTimelineView。
7. 动效、减少动效、窄窗口和无障碍完善。
8. 全量静态检查、前端测试、Rust 测试、生产构建与视觉审查。
