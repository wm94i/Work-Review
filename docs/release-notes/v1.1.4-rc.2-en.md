# Work_Review v1.1.4-rc.2 (English)

Second release candidate for 1.1.4, covering Windows portable mode, avatar transparency recovery and migration rollback protection added after rc.1. For testing only: stable `1.1.3` remains Latest, and the published `v1.1.4-rc.1` is unchanged. Back up your complete data directory before installing or migrating.

### Added
- **Windows portable data directory** (#182): the portable ZIP includes an empty `Data` folder. When it exists beside the EXE, the database, configuration, screenshots and update settings stay there, ahead of this PC's saved location. The app neither reads nor changes that location preference and does not import old data automatically. Without the marker, existing storage behavior is unchanged. An unreadable or unwritable directory fails explicitly instead of silently falling back; no new settings page is required.
- **Portable update protection**: stable/test update checks open the selected release page for a manual ZIP download; the backend rejects installer-based updates in portable mode. Exit, replace the EXE and preserve the existing `Data`. External data-directory migration is disabled in portable mode. Packaging includes only the executable, instructions and an empty `Data`, never existing private data.

### Fixed
- **Black avatar background after display recovery** (#190): on display-on/resume and when showing the avatar again, restore the existing window's native transparency on the GUI thread. Coalesce adjacent notifications and skip recovery if the display is off again or the avatar is hidden. Do not rebuild the WebView, change bubble styling, position, size or click-through, steal focus during recovery, or add continuous polling. This fixes the reproduced native-transparency-loss mechanism; actual monitor-off/on and reporter-device acceptance remain separate.
- **Migration rollback backups**: preserve unrestored destination data and report its backup path if rollback is blocked. Remove the empty backup directory only after complete restoration, rather than recursively deleting a potentially unique copy.

- **Pre-release security dependencies**: align all SQLite consumers on `rusqlite 0.41.1` / `libsqlite3-sys 0.39.1`, bundling SQLite `3.54.1` to fix possible uninitialized-memory disclosure when opening a crafted database/WAL pair (RUSTSEC-2026-0459). Update the OpenSSL Rust bindings to `0.10.80` for OCSP URL UTF-8 validation and AES key-wrap buffer sizing (RUSTSEC-2026-0474/0476/0477). No application schema change is introduced. Regressions use synthetic old-SQLite database/WAL files to verify migration, statistics, backup and reopen, and retain rejection of overflowing query limits.

### Updating and using portable mode
- Installed rc.1 users can enable **Receive test versions** on About and use the existing check button to receive rc.2. Test updates still require confirmation. Windows installer and macOS updates retain signature verification and the independent official SHA-256 check. Linux and portable mode use the selected release page for manual updating.
- Stable `1.1.3` users must manually install an RC for the first trial. Users who do not opt into test versions are not automatically upgraded to this RC.
- Switching to portable mode does not move history automatically. Fully exit the old app, back up its data directory, then copy the complete data you wish to retain into `Data`. Move the EXE and all of `Data` together. Never overwrite an existing `Data` with an empty folder during updates.
- WebView2 cache, autostart registration and user-selected external export paths remain system-managed; this is not a zero-system-footprint guarantee. `Data` may contain API keys: never share it publicly.

### Validation and known limits
- Local frontend checks passed with 775 tests; the Rust workspace passed 765 tests. Native Windows power-notification registration/unregistration passed separately. Windows debug building and macOS ARM cross-type-checking passed; the latter does not establish native linking or packaging.
- A native fault-injection fixture directly compiled the production recovery module. Its 24 stages passed, including black-background recovery, 100 notifications coalesced into one recovery, hidden/display-off guards, and preserved focus, bounds and click-through. **This is not an actual display-off reproduction** and does not identify the reporter's specific driver trigger. See [avatar transparency acceptance](../testing/windows-avatar-transparency.md).
- The #189 activity-accounting safeguards remain in place; real S0/S3 standby acceptance is still pending. Incorrect historical records are not recalculated automatically. The freeze-recovery rendering problem in #177 is not established as resolved.
- Portable-directory movement/data reads and archive contents have automated coverage. Actual cross-computer launch, installer upgrades, prolonged operation and multi-platform desktop acceptance remain incomplete.
- macOS remains ad-hoc signed and may require permissions again. Some upstream unmaintained/unsound and yanked-version warnings and existing platform limitations remain; a passing security gate does not mean all dependency warnings are gone. Automatic metadata cleanup remains disabled by default; `0` days means keep forever.
