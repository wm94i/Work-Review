# v1.2.0

Stable release combining the privacy, performance, reporting, export, and Svelte 5 changes from 1.2.0-rc.1 with new Personal Agent workflows. Existing RC releases and tags remain available. Back up the complete data directory before upgrading.

### Personal Agent workflows

- **Run Trace:** inspect run status, tool approvals, data boundaries, context compaction, and events in Work Assistant → Harness & Skills. Large tool results are held within the current run and read on demand.
- **Personal Skills:** create, edit, or remove local `skills/<name>/SKILL.md` workflows, loaded on demand in work-review mode.
- **Read-only routines:** daily, 15–1440 minute interval, and manual schedules run serially while the app is running. Local statistics or loopback models are used by default; each routine requires explicit opt-in before filtered work records can reach a cloud model.
- **External HTTP MCP:** desktop work-review mode requires human approval for every external tool call. General chat, bots, and routines do not use external MCP. Public endpoints require HTTPS; loopback access is explicit. Supports initialization, sessions, JSON / SSE, and session renewal. Tool outputs are treated as untrusted content.

### Main changes since 1.1.3

- Project time attribution, focus and context-switch metrics, Git commit references, Obsidian frontmatter / managed sections, and per-task model routing.
- Daily, weekly, and monthly reviews in four languages; CSV / JSON export; SHA-256 checked backups and restore with safety rollback; incremental semantic indexing and optional read-only bot questions.
- WebDAV sync v2 only shares allowed preferences and stricter privacy rules. Sender binding, Windows screenshot masking, credential redaction, and WebView / assistant network restrictions improve privacy boundaries.
- SQLite WAL reads, bounded queries, persistent Windows OCR / UI Automation workers, screenshot and activity accounting improvements, supervised background tasks, and the Svelte 5 migration.
- Linux / macOS build fixes and RustSec updates to `cookie` 0.18.3 and `url` 2.5.9.

### Final fixes

- Restore and safety rollback preserve local skills, routines, MCP settings, tokens, hidden assets, and empty skill directories in place.
- Loopback model connections pin loopback addresses and disable proxies and automatic redirects, including streaming, nonstreaming, and fallback requests.
- Ledger input / error previews and routine summaries redact complete quoted credentials, including spaces and escape sequences, before privacy filtering.
- MCP SSE returns after the matching complete response frame without waiting for the connection to close. Request-ID, session, size, and deadline validation remain in place.
- Includes the RC fixes for atomic Obsidian exports, privacy-cache invalidation, reasoning-model compatibility, UTF-8 streaming, scheduling, and configuration persistence.

### Upgrade and validation

- SQLite migrates automatically to schema 4 with a local run / event / audit ledger. New databases and backups cannot be used directly by older clients; downgrade by restoring a pre-upgrade backup.
- Bind Feishu, DingTalk, and WeCom senders before querying. Upgrade every device before enabling WebDAV v2 sync. Automatic indexing, bot natural-language queries, metadata cleanup, and routine cloud permission remain opt-in.
- Data-directory migration includes skills, routines, and MCP settings. In-app backups cover the database, app settings, and optional screenshots; separately secure `skills/`, `agent_routines.json`, and `mcp_clients.json`. Restore preserves those files on the destination machine. Changing an MCP endpoint clears its old token.
- Installed Windows and macOS builds use the existing stable update entry point. Linux and portable users update from the release page; preserve the original portable `Data` directory.
- Local Windows validation passed 800 Node tests, 20 component tests, 944 Rust tests, type checking, production build, formatting, warnings-denied check, and Clippy; two Rust tests are ignored. Publication requires this commit's cross-platform CI, security audit, and five-platform build / signature / asset / Linux GLIBC gates.
- Installation/upgrades, portable startup on another machine, long-running OCR/capture, real Windows standby, native macOS/Linux interaction, and real third-party MCP services have not received comprehensive desktop acceptance testing.
- Screenshot masking remains Windows-only with documented transparent-overlay limits. macOS remains ad-hoc signed and may require permissions again. Search queries reach the configured service; bot group replies remain visible to the group. Web tools retain the RC's documented proxy-redirect limitation.
