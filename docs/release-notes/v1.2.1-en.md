# v1.2.1

Maintenance release improving desktop-pet reliability and startup performance, tightening Assistant Extensions (Personal Agent Harness) execution semantics and security boundaries, and refining timeline detail interactions and Windows browser URL capture.

### Assistant Extensions (Personal Agent Harness)

- **Routine outcome accuracy:** routines expecting AI execution no longer report `completed` when the orchestrator degrades after a model error; skill-bound routines fail explicitly with an actionable message when no allowed AI model is available; ledger `timed_out` / `failed` / `cancelled` statuses are propagated accurately; local-stats fallback when a cloud model is blocked is labeled in the summary; daily scheduling uses `.earliest()` to avoid DST ambiguity.
- **Personal skill suggested tools & boundary hardening:** `allowed_tools` (also supporting kebab-case `allowed-tools` with validated tool names) is now injected into both the catalog prompt and `load_skill` output, while embedded spoofed start/end boundary prefixes are neutralized.
- **External MCP discovery cache:** desktop work-review discovery now uses a short-TTL cache (60s hit / 20s empty) keyed by a SHA-256 fingerprint of `(data_dir, blocked_self_port, enabled_servers)` with no plaintext tokens retained in cache keys, immediate read-path eviction of expired entries, and explicit invalidation after save, delete, or connectivity test.
- **Async ledger, timeout status & fail-closed artifact boundaries:** hot-path `RunLedgerRecorder` SQLite writes run on `tokio::task::spawn_blocking` with task-error warnings; deadline fallback now records `RunStatus::TimedOut`; compaction token estimation accounts for both assistant text and `tool_calls`; `read_run_artifact` classifies trust boundaries fail-closed by source tool without double-wrapping.

### Fixes & UX

- Expanded Windows browser address-bar UIA search depth while skipping web content trees, fixing missed Chrome URLs without exhausting the 350ms wait budget.
- Stopped auto-migrating legacy Ollama / Qwen3 presets into saved model profiles when AI is unconfigured; explicitly saved models still migrate normally.
- Redesigned timeline detail view with a screenshot canvas and flat info sidebar, URL copy, lightbox zoom, category/project controls, bottom delete action, dark-theme and narrow-window support, and keyboard focus traps with Escape close.
- Unified Assistant Extensions naming across all four UI locales, documentation, and READMEs.

### Desktop Pet Reliability & Performance

- Fixed click-through and hide-body toggle persistence, prevented settings snapshots from overwriting dragged positions or follow-ups, and avoided redundant writes on repeated "Remember" actions.
- Scoped input listeners strictly to lifecycle with generation isolation, fixed Windows punctuation/editing key mappings, cleared key state on hide, and reduced idle wakeups and redundant system queries.
- Moved Windows keyboard hook events onto a pre-allocated non-blocking queue with atomic mouse aggregation, eliminating lock waits in low-level callbacks.
- Initialized Linux Xlib multi-threading before GUI startup with error checking, and invalidated click-through caches on failed or undelivered updates for automatic retry.
- Isolated proactive AI requests with deadlines, backoff when unconfigured, privacy-keyed session caches on blocking threads, and cross-frame quiet periods after follow-up prompts.
- Preserved compact position across expand/collapse, skipped redundant window resizes, canceled stale size-correction timers, and computed bubble direction from current position after dragging.
- Split the desktop pet into a dedicated transparent entry page (`avatar.html`) so startup no longer loads main-window routes or sidebar, paused animations while hidden, reused precomputed Bezier coefficients, and added bounded Windows transparency recovery retries.
