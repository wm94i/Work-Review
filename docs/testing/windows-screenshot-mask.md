# Windows 截图隐私遮罩验收

> 对应改动：`src-tauri/src/screenshot_mask.rs`、`src-tauri/src/screenshot.rs`（`mask_sensitive_windows` / `sensitive_regions`）。
> 自动化覆盖：遮罩几何（遮挡、部分露出、半透明、负坐标副屏、裁剪）与敏感判断的单元测试；真机窗口枚举冒烟测试（`--ignored`）。
> 本文档用于**真实桌面**验收，自动测试不能替代。

## 前置

1. 设置 → 隐私：把一个常用应用（如微信 / Slack）设为「忽略」或「脱敏」。
2. 确认截图已启用，截图模式为「活动窗口所在显示器」。
3. 运行冒烟测试确认窗口枚举可用：
   ```bash
   cargo test -p work-review --bin work-review -- screenshot_mask --ignored --nocapture
   ```

## 用例

| # | 场景 | 期望 |
|---|---|---|
| 1 | 前台为普通应用，被忽略应用窗口在旁边**部分露出** | 截图中露出部分为纯黑，前台窗口内容完整 |
| 2 | 被忽略应用窗口被前台窗口**完全遮挡** | 截图无黑块 |
| 3 | 被忽略应用窗口在**另一块显示器**（含左侧负坐标副屏） | 当前显示器截图不受影响；「全部显示器」模式下该窗口区域为黑 |
| 4 | 后台浏览器窗口标题命中敏感关键词（如含 `bank`） | 该窗口可见区域为黑 |
| 5 | 被忽略应用最小化 / 位于其它虚拟桌面 | 截图无黑块 |
| 6 | 远程上传开启 | 上传的图片与本地归档一致（已遮罩） |
| 7 | OCR 开启 | 遮罩区域内文字不出现在 OCR 结果中 |
| 8 | 高 DPI（150% / 200%）与混合 DPI 多屏 | 黑块与窗口边界对齐（偏差 ≤ 几个像素） |

## 已知边界

- 遮罩区域取截图**前后**两次窗口枚举的并集，覆盖截图期间窗口移动 / 置顶。
- 窗口数量超过枚举上限（可见 512 / 句柄 8192）时放弃本次截图（日志提示），不输出可能漏遮的图片。
- 分层窗口仅在显式 `LWA_ALPHA` 且 `alpha=255`、无色键时计为遮挡物；`alpha=0` 全透明窗口直接忽略；逐像素透明分层窗口、`WS_EX_TRANSPARENT`、本应用透明桌宠、`WDA_EXCLUDEFROMCAPTURE` 及自定义非矩形裁剪区窗口均不计为遮挡物（宁可多遮）。
- UWP 应用（托管于 `ApplicationFrameHost.exe`）会解析真实子窗口进程名；进程名无法读取的受保护窗口除关键词外还会按窗口标题分段匹配应用隐私规则。
- `WS_EX_NOREDIRECTIONBITMAP`（DirectComposition）窗口**计为遮挡物**：实测 Chrome、Windows Terminal、系统设置、UWP 宿主等常规不透明窗口都带此样式，按透明处理会把前台正常内容大面积涂黑。残余风险：第三方真正透明的 DComp 浮层下方的敏感窗口不会被遮罩。
- WGC 降级路径无法像素遮罩：截图前或截图后截图范围内存在敏感窗口时直接跳过本次截图（日志提示）。
- macOS / Linux 暂未实现窗口枚举遮罩，仍按前台应用判断隐私。
