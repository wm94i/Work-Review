# Windows 待机时长回归（#189）

## 预期与实现边界

- 待机、当前用户会话熄屏及恢复会切开活动段。睡前已观察但尚未落库的尾段只结算到最后一次连续采样时刻，未知的待机空档不回补给任何应用；该尾段仍遵守输入空闲和隐私忽略规则。
- 使用当前会话的 `GUID_SESSION_DISPLAY_STATUS`，不是物理控制台的显示状态；变暗（Dim）仍视为显示开启。
- 未收到电源通知时，以采样连续性兜底：采样中断超过 60 秒、时钟倒退或墙钟与单调时钟偏差超过 5 秒均重新开始活动段。
- 连续性检查针对每轮窗口采样，不针对截图周期；配置 600 秒截图不会每次被当成中断。
- 若进程确实卡住超过 60 秒，该段无观测时间不再估算成工作时间，宁可留空而非错误归属。
- 本次只阻止新错误，不自动删除、裁剪或重算已有历史记录。修复历史须先备份并核对系统事件。

## 自动验证

```powershell
cargo test --locked -p work-review --bin work-review activity_clock::tests
node --import tsx --test recordingContinuity.test.ts
```

Rust 测试包括真实 SQLite 的小时分布回归：模拟 01:14:45 → 09:29:50 中断，覆盖唤醒后同应用/不同应用及截图开/关，检查睡前正常尾段得到保留、旧记录终点不跨待机推进、睡眠小时未被填满、恢复后仅累计新的工作时间。

这些测试不等于已在真实 S0/S3 硬件上验收。

交互式 Windows 会话可额外执行非破坏性的原生通知注册/注销检查（该项在默认 CI 中跳过，不会主动休眠或改变电源设置）：

```powershell
cargo test --locked -p work-review --bin work-review windows电源通知应能无窗口注册并注销 -- --ignored
```

## 实机验收

先备份用户数据或使用测试数据目录；不要为测试关闭现有锁屏安全策略。记录测试版本、`powercfg /a` 的支持状态和截图配置。

1. 让一个真实应用位于前台并正常操作至少一分钟，记下当前时间与活动时长。
2. 合盖或通过系统菜单待机，等待数分钟；长待机另做一次跨午夜验证。
3. 开盖并立即使用键鼠，分别测试保持原应用和切换到另一应用。
4. 检查时间线、概览小时图和原记录：待机区间不得归入任一应用，旧记录终点不得漂移到唤醒时刻，醒来后正常新增活动。
5. 截图关闭/开启各做一轮；截图间隔取 5、30、600 秒，不能把正常的长截图周期误判为采样中断。
6. 在支持 S0 的笔记本和支持传统 S3 的设备上分别测试，不能用 S3 结果替代 S0 验收。

补充边界：

- 熄屏后后台维护唤醒但屏幕仍关闭：不计应用时长。
- 短于 60 秒的待机/熄屏：仍应由电源通知切段。
- 仅屏幕变暗、连续操作超过 10 分钟：不因本次保护机制被截断。
- 暂停/继续录制：新旧活动不跨暂停区间合并。
- 若使用远程桌面，确认当前会话仍可正确记录，不被物理控制台熄屏误停。
- 采集或截图进行中进入待机：恢复后不得保存跨越边界的旧截图，下一轮应正常继续。

若仍复现，请提供系统事件中睡眠/恢复的时间、受影响时段的脱敏活动记录（时间戳、duration、应用名、可执行路径）和应用日志中的电源通知注册错误。无需上传整个工作数据库或截图。
